1. Problem

India’s booming e-commerce sector demands faster and cheaper delivery to meet customer expectations. Companies require smart warehouse placement strategies to balance delivery speed and cost while staying within operational budgets.

The Research Problem (RP):

Inefficient placement of warehouses can result in increased costs, longer delivery times, and decreased customer satisfaction. Thus, there is a critical need to develop an optimization model that can help in deciding where to locate warehouses to best serve major cities across India.

The Research Question (RQ):

How can we determine the optimal warehouse locations across India to minimize the total delivery cost and time, under given constraints of budget and maximum delivery time?

3. Data

This section outlines the datasets used in the project, the data preparation techniques applied, and the assumptions made to support the optimization model for warehouse location planning.

3.1 Source Datasets

3.1.1 Pincode-Level Geographic Dataset

This dataset provides geospatial and administrative data at the pincode level for locations across India. Each entry includes a pincode identifier, the corresponding administrative district, and the geographic coordinates (latitude and longitude). It enables spatial modeling of delivery logistics and helps in associating demand with physical regions on the map.

3.1.2 Amazon E-Commerce Sales Dataset

The second dataset comprises order-level transactional data from Amazon India. For each order, key variables include the shipping pincode and the number of items sold. These quantity values were used as a proxy for estimating regional e-commerce demand. While the dataset does not include geospatial coordinates, these were integrated by linking the shipping pincode with the pincode-location dataset.

3.2 Data Preparation and Integration

To prepare the data for modeling, the following preprocessing steps were undertaken:

  • Demand Aggregation: The sales data was grouped by shipping pincode, and the quantity values were summed to estimate total demand per location.
  • Merging Spatial Data: The aggregated demand values were joined with the geographic dataset using pincode as a key, enriching each record with district and location coordinates.
  • Data Cleaning: Records with missing or invalid demand or coordinate values were removed to ensure consistency and model readiness.

The resulting dataset includes pincode-level demand points, each tagged with a district and corresponding latitude and longitude. This serves as the demand input to the optimization model and is referred to as the demand points dataset.

3.3 District-Level Aggregation for Warehouse Candidates

To determine suitable warehouse locations, it was assumed that warehouses are to be built only in high-demand regions. Therefore, the demand data was aggregated at the district level:

  • Total demand was computed by summing demand across all pincodes within each district.
  • The centroid of each district was estimated using the average latitude and longitude of its constituent pincodes.

Districts were then ranked based on total demand, and the top 20 districts were selected as potential warehouse hub locations. These form the candidate warehouse locations dataset.

3.4 Distance Matrix Generation Using Haversine Formula

To evaluate delivery cost and time between each demand point and each warehouse candidate, we computed pairwise geographic distances(in kilometre) using the Haversine formula:

\[ Distance_{i,j} = R \cdot 2 \cdot \arctan 2 \left( \sqrt{a}, \sqrt{1 - a} \right) \]

where

\[ a = \sin^2 \left( \frac{\Delta \phi}{2} \right) + \cos(\phi_1) \cdot \cos(\phi_2) \cdot \sin^2 \left( \frac{\Delta \lambda}{2} \right) \]

  • \(\phi =\) latitude in radians

  • \(\lambda =\) longitude in radians

  • \(R =\) radius of Earth (\(\approx 6371 \, \text{km}\))

Using this formula:

  • Each row in the matrix represents a demand point

  • Each column corresponds to a warehouse candidate

  • Each cell gives the straight-line distance (in km) between the two

The calculation was implemented in R using a row-wise distance function. The result was saved as Distance_Matrix.csv.

3.5 Final Prepared Datasets

The preprocessing steps produced the following three datasets, each saved in CSV format:

  • Demand Points Dataset (Demand_points.csv): Contains pincode-level demand estimates and geospatial locations.
  • Warehouse Candidates Dataset (Warehouse_points.csv): Includes the top 20 demand-heavy districts considered for warehouse siting, along with centroid coordinates.
  • Distance Matrix (Distance_Matrix.csv): A matrix of pairwise distances (in km) between demand points and warehouse candidates.

3.6 Assumptions and Limitations

Several assumptions were made during data preparation, in line with standard practices in location modeling:

  • In the absence of actual shipment volumes, Qty was assumed to be proportional to e-commerce demand.
  • Latitude and longitude values were used to approximate delivery distances, ignoring actual road or transport network constraints.
  • District centroids were approximated by averaging the coordinates of associated pincodes.
  • No information was available on land cost, transportation cost, or budget constraints at this stage; these are incorporated through assumptions in the modeling phase.

4. Analysis

4.1 Warehouse Location Problem - Basic Formulation

Let’s define:

  • \(I=\) Set of potential warehouse locations.
    (Extracted from Warehouse_points.csv)

  • \(J=\) Set of demand points/cities.
    (Extracted from Demand_points.csv)

  • \(d_{i,j}=\) Distance/delivery cost from \(i\) to \(j\).
    (Extracted from Distance_Matrix.csv)

  • \(N =\) Maximum number of warehouses, to be chosen.

  • \(n=\) Number of potential warehouses.
    (20 assumed here)

  • \(h_j=\) Demand at city \(j\).
    (Extracted from Demand_points.csv w.r.t “pincode”)

  • \(F=\) Random list to model the list of prices, of setting up a warehouse at \(i^{\text{th}}\) location.
    (Generated a random list of values in range ₹20–40 lakh)

  • \(B =\) Chosen budget for setting up all the warehouses.
    (The budget \(B\) was chosen dynamically to reflect a realistic constraint on capital investment. Fixed setup costs for each warehouse were randomly generated between ₹20-40 lakh. The minimum required to build the cheapest 5 was computed, and then the final budget was randomly picked from the range:

    \[ B \in \left[ \sum_{i=1}^5 F_{(i)}, \sum_{i=1}^n F_i \right] \]

    • \(F_{i}\) denotes the fixed cost of setting up warehouse \(i\) (corresponding to candidate location \(i\)).
    • \(F_{(i)}\) denotes the \(i^{\text{th}}\) smallest fixed cost after sorting all \(F_{i}\)’s in ascending order.

    This ensured feasibility while introducing real-world trade-offs into warehouse selection.)

  • Rate = ₹ 1.775 / km.
    To estimate delivery cost per kilometer, we considered an average of fuel efficiencies of commonly used vehicles like bikes and cars. Based on typical mileage values and current fuel prices, the cost was approximated to ₹1.775/km. This serves as a realistic average for modeling delivery expenses in our optimization.

  • \(T_{\text{max}} =\) Maximum allowable delivery time per demand point.
    (Derived from the distance matrix using the Haversine formula. To ensure practical enforceability, the maximum value in the matrix was reduced by 2000 km to remove extreme long-distance outliers. This adjusted distance was then divided by an assumed average speed of 50 km/h to convert it into hours. Mathematically: \[ T_{\text{max}} = \frac{\text{max}(d_{i, j}) - 2000}{\text{Average Speed}} = \frac{d^* - 2000}{50}\ \] where \(d^*\) is the maximum Haversine distance observed. This enforces a realistic time-bound service constraint and prevents the model from assigning demand to extremely distant hubs.)

  • \(x_i\) ; \(x_i \in \{0,1\}\) (1 if warehouse is opened at \(i\), 0 otherwise)

  • \(y_{i,j}=\) fraction of demand at \(j\) served by warehouse \(i\).

  • \(t_{i, j}=\) The travel time between location \(i\) and demand point \(j\) is given by:

\[t_{i, j} = \frac{d_{i, j}}{\text{Average Speed}}\] where:- \(t_{i,j}\) = travel time (hours) - \(d_{i, j}\) = Haversine distance between locations (km) - Average Speed = 50 km/h (assumed constant)

This conversion enables time-based service constraints in the optimization model.

Objective: Minimize delivery cost

Minimize : \[ Z=\sum_{i \in I, j \in J} c_{i,j}h_{j}y_{i,j} +\sum_{i \in I} f_i \cdot x_i \]

Constraints

Each city’s demand must be fully satisfied: \[ \sum_{i \in I} y_{i,j} = 1\space \space \forall \space\space j\in J\]

Demand assignment only to open warehouses: \[ y_{i,j} \leq x_i \space\space\space\space\forall i \in I, j \in J\]

Budget constraint: \[ \sum_{i \in I} f_i \cdot x_i \leq B \]

Maximum delivery time:
\[ \sum_{i \in I} t_{i,j} \cdot y_{i,j} \leq T_{\max} \space\space \forall\space j \in J\]

Binary Constraint: \[ x_i \in \{0, 1\} \space\forall\space i \in I\]

Non-negativity constraint: \[ y_{i,j} \geq 0 \space\forall\space i \in I, j \in J\]

4.2 Model Implementation & Execution

The model was encoded in Python using PuLP and solved via the CBC solver. Inputs were read directly from the prepared datasets. Setup costs for candidate warehouses were randomly sampled from a uniform distribution, and a feasible budget was drawn accordingly. Time constraints were imposed by converting Haversine distances to hours using a constant average speed. Post-solution, optimal warehouse activations and fractional demand allocations were extracted and exported for evaluation.
